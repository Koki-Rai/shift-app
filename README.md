# シフト自動作成アプリ

## 背景・課題

大学祭のサークルの出し物として、音楽喫茶を運営していた。サークル員のバンド演奏を聴きながら、ケーキなどを注文できる形態である。

2年生のとき、シフト作成係の一人としてこの作業を担当した。サークル員のシフト不可時間をGoogle Formで調査し、全員をExcel上で各時間・各役割に手作業で割り当てていく、というものだった。当時は完全な手作業で、重複の警告も、各人のシフト回数の表示もなかった。特に大変だったのは、次の二点だった。
- **各人の予定を文字で確認しながら割り当てること**：Google Formの回答を一つひとつ読み、演奏時間などと衝突しないよう手作業で埋めていく必要があった。
- **バンドの演奏順の変更への対応**：演奏順は直前に変わることがあり、そのたびに、演奏中の人をシフトから外して組み直す必要があった。

この経験から、次の代のために、以下のExcelの仕組みを自作した。

- **重複の色付け**：同じ時間に2つの役割へ割り当ててしまった場合、該当セルに色がつく。
- **シフト回数の可視化**：各人が何回シフトに入っているかを出力し、偏りを調整しやすくする。

これらは後輩に引き継がれ、改修されながら現在も使われている。

しかし、この仕組みにも限界があった。重複の色付けは「割り当てた後」にしか気づけず、回数の可視化も結局は人が見ながら手作業で調整する必要があった。予定との衝突（演奏時間など）も、Google Formの回答を目で確認しながら避けるしかなかった。そして何より、Excelへの手打ちである以上、作成に時間がかかった。

本アプリは、これらを「制約」と「最適化」によって手作業に頼らず自動で解決することを目指す。特に、バンドの演奏スケジュールを入力すると演奏者が自動的にその時間はシフト不可となり、演奏順が変わっても再生成するだけで対応できることを、中心的な機能として想定している。

## できること

ボタン一つで、以下を満たすシフト表を自動生成できる。

- **役割の掛け持ちが起きない**（同じ時間に2つの役割に入らない）
- **各人の予定と衝突しない**（バンド演奏中などの時間には割り当てない）
- **各時間・各役割に必要な人数がちょうど埋まる**
- **シフト回数の偏りが少ない**

これらを「制約」として記述しているため、条件を破ったシフトは原理的に生成されない。従来のように、割り当てた後に目視で確認する必要がなくなった。

## 技術的な工夫

### 現場の課題を「制約」として定式化した

シフト作成を、数理最適化ソルバー（Google OR-ToolsのCP-SAT）を用いて解いた。
その際、現場で守るべきルールを、以下の制約として記述した。

- **掛け持ちの禁止**：各(従業員, 時間)について、割り当てられる役割を1つ以下に制限（Σ_role x[e,t,role] ≤ 1）
- **予定との衝突回避**：演奏時間など入れない時間には、該当する割り当て変数を0に固定
- **必要人数の充足**：各(時間, 役割)に、必要な人数がちょうど割り当たるよう制約

（"誰を・どの時間・どの役割に割り当てるか"を、x[従業員, 時間, 役割]という0/1変数で表現し、上記を制約として与えた。）

### 「間違いの検知」から「間違いの防止」へ

従来のExcelでは、重複を色で警告していたが、これは割り当てた後にしか気づけない事後的な検知だった。
本アプリでは、掛け持ちや予定衝突を制約として記述することで、条件を破る割り当てがそもそも生成されないようにした。目視確認が不要になった。

### 偏りの調整を、目的関数として自動化した

従来は各人のシフト回数を見ながら手作業で偏りを調整していた。
本アプリでは、「最も多い人と最も少ない人のシフト回数の差」を最小化することを目的関数とし、この調整を自動化した。

## 使用技術

- Python
- Streamlit
- OR-Tools
- pandas

## 使い方

### 環境構築

```bash
# 必要なライブラリをインストール
pip install ortools streamlit pandas
```

### 起動

```bash
streamlit run app.py
```

起動すると、ターミナルにアクセス用のURL（通常は `http://localhost:8501`）が表示されるので、それをブラウザで開く。

## 今後の課題

- **バンド演奏スケジュールとの連動**：演奏順を入力すると、演奏者が自動的にその時間シフト不可になる仕組み。演奏順の変更にも再生成で対応できる（本アプリの中心的な狙い）。
- **本番規模への対応**：現在は最小構成（数名・数役割）。実際の約50名・約10役割への拡張。
- **公平性の高度化**：シフトに入れる時間が人によって偏る場合に備え、コマ数ではなく「入れる時間に対する充足率」で公平性を測る。
- **急な予定変更・欠員への対応**：空いている人の一覧表示など、運用中の変更を支援する機能。
- **入力・共有の仕組み**：Google Formからの自動入力、複数人でのWeb上での編集、公開URLでの共有（デプロイ）。
